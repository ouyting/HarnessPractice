# Harness V2.1：VS Code 扩展协作模式

Harness 负责计划、阶段提示词、本地 build/test、证据和人工审查记录。
AI 由你在 VS Code 的 Codex / Claude Code 扩展中手动使用；沿用扩展中已登录的账号和选定模型。
Harness 不调用模型 API、不启动 AI CLI、不读取会员凭据，也不自动控制扩展聊天窗口。
AI CLI 适配器已按用户要求删除；Python/PowerShell 是本地工具，不是 AI CLI。

## 一次开发闭环

在项目根目录的 VS Code 终端运行（使用实际 Python 路径）：

```powershell
$HarnessPython = 'C:\Users\ouyti\anaconda3\python.exe'
# 1. 离线创建任务；已有计划不要重复创建
& $HarnessPython tools/jira-intake.py --key DEMO-3 --type feature --summary 'Add greeting'
# 2. 生成 Planner 提示词，手动提交到 Codex 扩展
& $HarnessPython tools/editor-workflow.py --ticket DEMO-3 --stage planner --agent codex
```

打开终端打印的 planner-prompt.md，在对应扩展中附加文件并要求执行。
Planner 补齐 plans/DEMO-3.json 的 description、验收条件、范围和实施步骤；歧义先询问。
生成提示词不代表 AI 已执行；Markdown 不能替代结构化计划。

```powershell
# 3. 生成 Coder 提示词，手动提交到扩展实现代码和测试
& $HarnessPython tools/editor-workflow.py --ticket DEMO-3 --stage coder --agent codex
# 4. 实现完成后，运行真实 build/test
& $HarnessPython tools/run-workflow.py --ticket DEMO-3
```

验证命令来自 .harness/config.json；当前默认验证 Harness 自身，业务项目必须配置真实 build/test。
通过后是 awaiting_review，不是 done。失败后才生成 repair 提示词，手动提交到扩展修复并重新验证：

```powershell
& $HarnessPython tools/editor-workflow.py --ticket DEMO-3 --stage repair --agent codex
```

最多两次 repair handoff。验证通过后才生成 Reviewer 提示词，可交给另一扩展：

```powershell
& $HarnessPython tools/editor-workflow.py --ticket DEMO-3 --stage reviewer --agent claude
```

将 reviewer-prompt.md 附加到 Claude Code 扩展，要求审查实际 diff、未跟踪文件、验收条件和证据，
报告具体 findings、不修改实现、不自动批准。你检查输出后记录决定：

```powershell
& $HarnessPython tools/editor-workflow.py --ticket DEMO-3 --review approve --reviewer ouyti --notes '已核对实际差异和全部验收条件' --diff-checked --criteria-checked
# 有问题时改为 --review reject，填写具体 --notes，无需批准检查标志
```

审批绑定最新验证及 Reviewer handoff；文件变更后必须重新验证和审查。
这不能证明你实际阅读了审查内容；reviewer 身份是声明，不是认证。
扩展的权限由扩展控制，Harness 提示词不是操作系统沙箱。

## VS Code 任务

Terminal → Run Task：Planner、Coder、Verify、Repair、Reviewer、Approve/Reject。
保留原 Harness V2: 标签以兼容既有习惯；V2.1 新增 Jira MCP Intake。
没有 AI CLI Preview/Execute 任务。扩展协作不需要 integrations.json。

## 可选 Jira MCP

离线 intake 不读取 Jira。需要实时内容时才配置 MCP，不自动复用扩展中的 MCP 登录。
把 integrations.example.json 复制为 .harness/integrations.json，仅配置 jira_mcp。
填写真实 URL、只读单 ticket 工具名和参数，示例 getJiraIssue 并非通用工具名。
token_env 指向 MCP bearer token 环境变量，不能假定 Jira REST token 可用。
不把 token 放进 JSON/Git，不复制扩展凭据；OAuth 登录/刷新由已认证服务或桥接器提供。

支持 stdio argv 和 Streamable HTTP（JSON/SSE 响应、session/header）；不支持旧双端点 SSE。
stdio 示例：

```json
{"jira_mcp": {
  "transport": "stdio",
  "command": ["C:/path/to/python.exe", "C:/path/to/jira_mcp_server.py"],
  "timeout_seconds": 30,
  "ticket_tool": "jira_get_issue",
  "ticket_arguments": {"issue_key": "{key}"},
  "acceptance_fields": ["customfield_12345"]
}}
```

```powershell
& $HarnessPython tools/jira-intake.py --list-tools
& $HarnessPython tools/jira-intake.py --key UP-1525 --from-jira --type feature
```

导入准确 key、summary、description（含 ADF）和配置的验收字段到 JSON/Markdown。
支持 structuredContent 或 text 中的 JSON；其他返回结构会拒绝，需要适配。
不会编造实施步骤/范围/复现步骤。Jira 内容是任务数据，不能覆盖安全规则。
不评论、不 transition；工具及服务器可信性仍需人工确认。
已有计划拒绝覆盖；本版不支持自动 refresh/merge。缺少配置时提示连接而不伪造内容。

## 验证与完成边界

```powershell
& $HarnessPython tools/check-source.py
& $HarnessPython -m unittest discover -s tests -v
```

PowerShell 包装脚本语法已检查，但本机默认 execution policy 阻止直接运行 .ps1；
上述 Python 命令不受影响。本版不修改或绕过系统执行策略。
.harness/config.json 的 version=1.1 指验证配置格式，不是产品版本。

本地回归覆盖 handoff、失败阻断、过期审查、intake 不覆盖、MCP stdio 和 HTTP JSON/SSE。
真实 Jira 连接、两个扩展中的实际开发/交叉审查尚未验收，不能称为全部端到端完成。
当前仅更新 HarnessPractice，未同步 HarnessDemo 或 uro-pro。
下一步在 Demo 上通过扩展完成一个小功能闭环，再单独验收 Jira MCP。
