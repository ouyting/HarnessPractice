# Harness V2.1：VS Code 扩展协作模式

Harness 管理计划、阶段提示词、本地 build/test 和显式审查证据。
Codex 或 Claude Code 在 VS Code 扩展中执行 AI 工作；使用扩展已有的 MCP、登录账号和所选模型。
Harness 不执行 AI CLI，不调用模型 API，不创建独立 Jira MCP 连接，不复制扩展凭据。

## Jira Intake：读取与更新已有计划

```powershell
python tools/jira-intake.py --key UP-1525 --agent codex
# 或使用 Claude Code 扩展已有的 Jira MCP
python tools/jira-intake.py --key UP-1525 --agent claude
```

命令只创建唯一的 .harness/runs/<KEY>/jira-intake/<ID>/prompt.md 和 manifest.json，
不会读取 Jira，也不会创建、覆盖或修改 plans 下文件。
打开输出的 prompt.md，在所选扩展中附加文件并要求执行：

1. 扩展使用自己的现有 Jira/Atlassian MCP 只读查询 ticket。
2. 检查现有 JSON、对应 Markdown、用户笔记和额外字段。
3. 按 .harness/templates/jira-ticket-plan.md 整理原文、核心需求、验收条件、范围和实施建议。
4. 展示两个文件的拟更新差异，等待你明确确认，不能提前写入。
5. 确认后重新检查文件是否变化；如有变化重新展示差异并确认。
6. 只更新该 ticket 的两个计划文件；标题变化时不另建重复 Markdown。
7. 校验结构与两文件一致性，未澄清项保持 needs_clarification，不假装业务验证通过。

生成提示词不是扩展已经读取 Jira或完成更新。普通 Python 脚本不能直接控制扩展会话；
你必须手动交接提示词。确认机制是扩展应遵守的工作流指令，不是脚本实现的文件写入权限锁。
扩展若没有可用 Jira MCP，会询问你在该扩展连接；不要求填写 integrations.json。

## VS Code 任务

Terminal → Run Task → **Harness V2.1: Jira Intake (Extension MCP)**。
输入 ticket，选择 codex 或 claude。任务仍只准备提示词，输出路径供你附加到扩展。
所有任务使用 Python 扩展当前选中的解释器，Windows 经显式 PowerShell shell 调用，
使用强引用避免路径和参数转义问题。需要启用 Microsoft Python 扩展并选择解释器。
不使用人工 Python 路径输入框或机器固定的 Python 路径。

## 离线占位模板（兼容旧用法）

```powershell
python tools/jira-intake.py --key DEMO-3 --offline --type feature --summary "Add greeting"
```

只有此离线模式会由脚本创建 plans/<KEY>.json 与 Markdown，已有文件仍拒绝覆盖。
旧 --key/--type/--summary 命令继续作为离线模式；--from-jira 仅保留为交接模式兼容别名，
不再连接 MCP；--config 和 --list-tools 已删除。

## 后续开发闭环

```powershell
python tools/editor-workflow.py --ticket UP-1525 --stage planner --agent codex
# 把提示词交给扩展执行规划，先解决歧义
python tools/editor-workflow.py --ticket UP-1525 --stage coder --agent codex
# 把提示词交给扩展实现，再运行真实业务 build/test
python tools/run-workflow.py --ticket UP-1525
# 通过且文件未变化后，准备审查提示词，交给扩展审查
python tools/editor-workflow.py --ticket UP-1525 --stage reviewer --agent claude
```

失败时才生成 repair 提示词，最多两次 handoff。通过验证只是 awaiting_review，
实际审查后由你显式记录 approve/reject；不自动批准、不回写 Jira。
当前默认命令验证本仓库示例，不能作为 UP-1525 业务验收证据。
.harness/config.json 的 version=1.1 是验证配置格式，与产品 V2.1 不冲突。

## 本地检查

```powershell
python tools/check-source.py
python -m unittest discover -s tests -v
```

PowerShell .ps1 包装脚本仍受本机 execution policy 限制；本文 Python 入口不依赖修改执行策略。
Jira 独立客户端和配置示例已退役；历史副本位于 .harness/runs/retired-jira-client/（忽略 Git）。
若本地曾有 integrations.json，迁移时保留至备份或作为未读取的历史文件，不参与任何运行。
不删除 Codex/Claude 扩展中已配置的 MCP，也不更新 uro-pro。

迁移本身不读取或更新 UP-1525 计划。真实 MCP 访问及更新在你手动交接后才发生。
