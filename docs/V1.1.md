# Harness V1.1：真实验证与审查

V1.1 执行本地项目命令并保存证据。开发者或 coding agent 负责规划和实现；流程脚本校验计划、执行构建和测试、记录显式审查。它不会自动生成代码或替代人工审查。

## 1. 本地录入 ticket

```powershell
python tools/jira-intake.py --key PROJ-123 --type feature --summary "支持报告导出"
```

补齐生成的 `plans/PROJ-123.json`：description、acceptance_criteria、scope、implementation_steps 均必填。Bug 还需 reproduction_steps 和 expected_behavior。原 Markdown 计划继续保留，结构化 JSON 是流程的校验输入。

## 2. 配置项目真实命令

编辑 `.harness/config.json` 的 build/test.command（参数数组）与 timeout_seconds。使用 `{python}` 代表当前 Python；PowerShell 脚本用 `["powershell", "-NoProfile", "-File", "tools/build.ps1"]`。命令始终在项目根目录执行。

HarnessPractice 默认验证自身源码和回归测试。迁入业务项目后必须换成业务构建和测试命令。不要配置任何命令回调 run-workflow.py，避免递归；本仓库 build.ps1/test.ps1 直接执行源码校验与单元测试。

## 3. 实现后验证

```powershell
python tools/run-workflow.py --ticket PROJ-123 --workflow feature
```

缺少计划/验收条件或类型不匹配会停止。构建失败则不执行测试；测试失败或超时进入 blocked。全部通过只进入 awaiting_review（退出码 0 表示验证通过，不能理解成开发完成）。

证据保存在 `.harness/runs/PROJ-123/<run_id>.json` 和 latest.json，包括命令、时间、输出、退出码及项目快照哈希。内容变化会使旧审查失效。当前快照保守地覆盖整个项目，排除 .git、Python 缓存、Harness runs 与 memory；业务构建输出若写入其他目录会阻止审查，需要项目适配，不应随意排除源码。日志可能含内部信息，不应默认提交或上传。

`--verify-only` 会真实执行命令但不保存 Harness 记录；命令本身仍可能产生构建产物，且这一模式不能进入审查。

## 4. 阅读代码与测试证据，再记录审查

先检查实际 diff（含新建未跟踪文件）、验收条件及运行证据。审查者身份与文字结论由操作人填写；脚本记录声明，不负责验证人的身份或替人阅读代码。

```powershell
python tools/run-workflow.py --ticket PROJ-123 --review approve --run-id <实际run_id> --reviewer "你的名字" --notes "逐条验收、检查改动范围和测试证据后的具体结论" --diff-checked --criteria-checked
```

approve + 两项确认才进入 done。reject 进入 blocked，修复后重新验证。旧 run_id、失败的运行或验证后文件变化均不能批准。

## 5. 验证 Harness 本身

```powershell
.\tools\build.ps1
.\tools\test.ps1
```

回归测试覆盖缺失验收条件、类型不匹配、Bug 复现要求、构建/测试失败、超时、修复重跑、待审查、批准/拒绝、过期快照和旧运行审查。

Jira 持续为可选连接。仅在实时读取 ticket 或回写时提示连接 MCP；本版本不访问 Jira。

Windows 若阻止脚本执行，可仅对当前调用使用 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/test.ps1`。若 python 命令指向 Store 占位程序，使用实际安装路径：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/test.ps1 -Python C:\Users\ouyti\anaconda3\python.exe`；工作流同样可用 `& 'C:\Users\ouyti\anaconda3\python.exe' tools/run-workflow.py --ticket PROJ-123`。
